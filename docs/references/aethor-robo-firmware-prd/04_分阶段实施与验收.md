# 04 分阶段实施与验收

## 1. 执行原则

- 每个阶段只扩大一个风险面：先身份和反馈，再单轴，再七轴。
- 每个阶段必须同时更新固件、协议样例、测试记录和上位机适配状态。
- 未满足退出条件不得把下一阶段功能接到整机。
- 每阶段在退出条件全部通过后创建独立 Git commit；远端由负责人手动 push。阶段未完成时只更新 handoff，不提交伪完成记录。提交信息建议：`phase(N): <outcome>`。
- 每阶段结束填写 [06_测试矩阵与交接模板.md](06_测试矩阵与交接模板.md) 中的 handoff，不把计划项写成已完成项。

## Phase 0：契约与台架配置冻结

### 目标

冻结七轴身份、ID、关节坐标、协议版本和可测的工程基线，不驱动电机运动。

### 固件任务

- 备份现有 `.ioc` 和 Keil 工程，记录工具版本、编译器版本、FDCAN1/UART/FreeRTOS 配置。
- 建立 `App/` 目录和单向依赖边界。
- 建立 `JointConfig[7]`，写入 CAN ID 1–7、Master ID 11–17；限位、方向、速度、加速度仍可标 `TBD`，但未补齐时禁止使能。
- 实现构建信息、`controller_id`、`arm_id` 和协议版本常量。
- 建立事件 ID 表、诊断计数器和无动态分配约束。

### 上位机同步任务

- 新增协议适配器占位 `aethor-arm-ascii-v1`。
- Aethor_robo Profile 明确首组 `arm-01`、7 DOF；未验证限位显示为待配置，不再使用占位范围执行运动。
- 控制台设备选择能区分 Dummy 与 Aethor_robo，但硬件控制保持禁用。

### 验收

- CubeMX 重新生成后工程能在 Keil 无错误编译。
- Map 文件中无意外堆增长；业务模块不在 CubeMX 生成区。
- 配置静态检查能发现重复 ID、缺失关节和非法范围。
- 形成当前硬件接线图、工具版本和参数 TBD 清单。

### 阶段提示词

> 在现有 STM32H723 + FreeRTOS + FDCAN1 + UART 工程中执行 Phase 0。先读取真实 `.ioc`、Keil 工程和当前代码，不改变已经工作的外设配置。按《01 产品需求与系统架构》建立 App/Config、Protocol、Arm、Motion、Motor、Telemetry、Platform 分层，新增七轴 JointConfig 与启动配置校验。CAN ID 固定 1–7，Master ID 固定 11–17。没有实测数据的方向、软限位、速度、加速度和 MIT 增益保持显式 TBD，并使使能条件失败。提供编译结果、Map 摘要、CubeMX 再生成验证、文件清单和 Phase 0 handoff；不要驱动电机。

## Phase 1：单电机供应商协议验证

### 目标

在卸载或机械安全隔离的条件下，只接 J1 对应的一套 3519/3520，证明 CAN 帧、ID、单位、反馈和两种模式可用。

### 固件任务

- 从供应商 H7 FDCAN 示例提取纯 `DmMotorCodec`，不复制阻塞循环。
- 实现 MIT、位置速度、使能、失能、清错和反馈解码。
- 实现寄存器读取，记录 ESC_ID、MST_ID、CMODE、PMAX、VMAX、TMAX 和版本。
- 为编解码建立 PC 侧纯 C 单元测试和固定字节向量。
- 实现单电机 1–5% 低速、小角度测试入口；默认去使能。

### 上位机同步任务

- 做协议帧日志查看器，显示 request ID、CAN ID、模式和原始故障码。
- 不接入 3D 控制，只显示单电机台架数据。

### 验收

- 反馈帧的 Master ID 与配置一致，D0 的电机 ID 交叉校验通过。
- 手动转动时位置和速度符号稳定，单位经已知角度验证。
- 位置速度模式低速小角度运动可停止、可失能。
- MIT 模式在低 Kp/Kd、`t_ff=0` 下可控；Kd 不为 0。
- 断 CAN、过温/过流模拟或关闭驱动时能生成明确故障。
- 记录实际 PMAX/VMAX/TMAX，不使用示例默认值代替。
- 验证 `0x7FF/0xCC` 查询是否被当前 DM3520 固件支持，并记录真实反馈行为。

### 阶段提示词

> 执行 Phase 1，仅使用一套 DM-S3519-1EC + DM3520-1EC。以本地 V1.1/V1.4 手册和 H7 FDCAN 示例为协议来源，实现非阻塞 DmMotorCodec 和 DmMotorTransport。验证 MIT 8 字节位域、位置速度 float32 小端、反馈帧、使能 FC、失能 FD、清错 FB，并实测 `0x7FF/0xCC` 查询兼容性。读取并记录 ESC_ID、MST_ID、CMODE、PMAX、VMAX、TMAX，禁止把示例的 12.5/45/18 当作实机值。模式切换若需要写参数和复位，只在维护流程执行并使对齐失效。先做编码单元测试，再做卸载低速小角度台架。输出原始 CAN 抓包、单位验证、故障验证和 handoff。

## Phase 2：七电机只读反馈与 CAN 负载

### 目标

从任意电机子集开始接入，最终扩展到七个驱动器；全程不使能运动，验证按 ID 映射、异常/冲突诊断、反馈完整性、接收实时性和总线预算。

### 固件任务

- 配置 FDCAN 精确过滤器接收 11–17。
- 完成 RX ISR → raw ring → CanRxTask → 七轴快照链路。
- 实现反馈年龄、序号、丢帧、overflow、bus-off 和 ID 不一致诊断。
- 实现 `present/valid/conflict` mask 和异常 ID 集合；ID >7 不映射，重复/低 8 位冲突只报告疑似证据。
- 实现 `GET_INFO/GET_CONFIG/GET_STATE/GET_JPOS/GET_MOTORS/GET_DIAG` 的最小串口版本。
- 在失能状态验证供应商 `0x7FF/0xCC` 显式反馈查询；后台轮转获取新反馈，但 GET_JPOS 本身不触发查询。
- `GET_JPOS` 只读快照，不发送 CAN 请求。

### 上位机同步任务

- C# 或临时测试客户端解析七轴查询，验证 1–7 对应 J1–J7。
- 控制台显示七轴反馈新鲜度和故障，但所有运动按钮禁用。
- 任意唯一 ID 子集都只驱动对应 J1–J7；缺失/冲突关节及受其影响的下游链灰显，不能按到达顺序映射。

### 验收

- 七个 Master ID 都能独立更新，无串轴。
- 手动转动每个轴时只有对应 J 值变化。
- 运行 30 分钟无 RX overflow、无任务锁死。
- CAN 分析仪记录平均/峰值负载、错误帧和反馈周期。
- 连续发送 `GET_JPOS` 不改变后台 CAN 轮询基线和反馈频率。

### 阶段提示词

> 执行 Phase 2，从 1 个驱动逐步扩展到 7 个并始终保持失能。实现按 D0 motor_id 1–7 映射、MST_ID 交叉校验、present/valid/conflict mask 和异常 ID 诊断；插线与回包顺序不得改变 J1–J7。先验证供应商 0x7FF/0xCC 显式反馈查询，失能状态由独立后台轮询器均匀获取反馈；GET_JPOS 只读快照，不临时触发 CAN。ISR 只搬运，CanRxTask 解码，ArmControlTask 发布一致性快照。分别验证缺失 ID、ID >7、可观测重复/冲突以及逐轴手动转动；最后在完整七轴条件下用 CAN 分析仪记录 30 分钟负载、周期、错误帧、overflow 和反馈年龄。上位机先做部分只读显示，不开放任何运动。

## Phase 3：正式串口协议与数字孪生只读同步

### 目标

完成 `aethor-arm-ascii-v1`，使 Aethor Studio V2 的实体模型稳定跟随七轴反馈。

### 固件任务

- 实现 DMA + IDLE 接收、512 字节有界行解析和 CRC-16。
- 实现请求号、查询、`SET_STREAM`、优先级 TX 队列和 50 Hz `JOINT_STATE`。
- 实现双缓冲/seqlock 快照，遥测不阻塞 250 Hz 控制任务。
- 实现协议错误码和重复请求缓存。

### 上位机同步任务

- 实现协议握手、版本/配置摘要校验、CRC、请求关联、250 ms HEARTBEAT 和断线重连。
- 实体模型只使用 `TEL JOINT_STATE.q_deg`。
- 显示反馈年龄、遥测频率、丢帧和 boot_id；反馈过期时模型状态明确失效。
- 保留幽灵模型，但下发按钮仍禁用。

### 验收

- 50 Hz 遥测持续 1 小时，CRC、帧丢失和序号间隙有统计。
- J1–J7 模型方向和转角与手动实机变化一致。
- 100 Hz 查询压力下控制/遥测任务无明显抖动；查询不增加 CAN 流量。
- 串口断开/重连后自动重新握手和恢复只读状态。
- 未知字段可忽略，非法列表、NaN、超长行和坏 CRC 被拒绝。

### 阶段提示词

> 执行 Phase 3，完整实现《02 上位机串口协议》。使用 UART DMA circular + IDLE、固定缓冲和 CRC-16/CCITT-FALSE。实现 HELLO、GET_*、SET_STREAM、ACK/RSP/ERR/EVT/TEL/DONE 结构及重复请求语义。默认 50 Hz 发布同代七轴快照，遥测拥塞丢旧保新，不能阻塞 CAN 和控制任务。同步实现 Aethor Studio V2 协议适配器，让实体 URDF 只跟随 q_deg，反馈过期时明确失效。完成坏帧、重连、1 小时遥测和压力测试。

## Phase 4：参考位对齐与单关节位置速度控制

### 目标

建立实机、固件关节角、滑条和 URDF 之间的统一坐标，并只开放单轴低速运动。

### 固件任务

- 为每轴确认 `direction`、机械参考姿态和软限位。
- 实现 `ALIGN_REFERENCE` 和本次上电 RAM 零偏。
- 驱动器已在维护流程统一配置为 POS_VEL；固件只核对模式并实现 `ENABLE/DISABLE/STOP/CLEAR_FAULT`，不提供日常 SET_MODE。
- 实现单轴测试开关；其余六轴保持目标等于当前反馈。
- 所有上电初始状态为 `UNALIGNED`。

### 上位机同步任务

- 提供参考位确认界面，显示本次会话是否已对齐。
- “目标对齐当前”使用最新 `q_deg`，不得用 URDF 默认值替代反馈。
- 只开放选中单轴、小角度、低速下发；显示固件最终结果。

### 验收

- 在参考姿态对齐后，七轴 `GET_JPOS` 与参考角误差在规定容差内。
- 每个轴正向拖动幽灵滑条，实机向同一语义方向运动，实体模型跟随反馈。
- 目标 5°、10° 的到达值与最终 `q_deg` 一致，无重复偏置或角度/弧度错误。
- 重启后重新进入 `UNALIGNED`，不会沿用旧零偏。
- 错误 COM/断线由上位机正确恢复；固件实时控制不依赖串口轮询。

### 阶段提示词

> 执行 Phase 4。先逐轴确定机械正方向、参考位和保守软限位，并同步写入固件和 Aethor_robo Profile。实现每次上电必须执行的 ALIGN_REFERENCE；GET_JPOS 返回对齐后的 deg，驱动 rad 转换只在固件完成。只用 POS_VEL 模式逐轴低速、小角度验证，其他关节保持当前位置。上位机“目标对齐当前”必须取最新反馈。逐轴记录命令角、反馈角、模型角、方向和误差，证明三者统一后才能退出阶段。

## Phase 5：七轴位置速度整组控制

### 目标

开放七轴整组目标和基础动作编排，验证共同开始、受限速度和最终到位。

### 固件任务

- 实现整组目标的原子校验、活动命令和 `DONE` 终态。
- 先采用位置速度模式策略 A：同时发送七个最终位置，并按统一期望时长计算每轴最大速度。
- POS_VEL 内部运动期间按每轴 50 Hz 继续显式查询反馈，不能只在发送目标时更新一次模型。
- 实现跟随误差、稳定窗口、超时和受控停止。
- 新运动在 `MOVING` 状态返回 `BUSY`，STOP 使用高优先级通道。

### 上位机同步任务

- 幽灵模型七轴目标一次下发，不逐轴发送。
- 动作编排仅在上一段 `DONE COMPLETED` 后发送下一段。
- 显示 RUNNING/SETTLING/COMPLETED/FAILED，不以 ACK 当作完成。

### 验收

- 20 组保守姿态往返，无越限、无指令卡死。
- 七轴最终误差与稳定窗口有记录。
- 测量各轴到位时间差，位置速度模式结果单独标注，不夸大为精确同步。
- 运动中 50 Hz 模型更新连续，查询和事件不打架。
- STOP 后可以再次发送下一条运动，无需复位软件。

### 阶段提示词

> 执行 Phase 5，在 POS_VEL 模式实现七轴原子 MOVE_JOINTS。所有目标先同时校验，再按共同期望时长计算每轴 v_des，并在一个控制周期内排入 7 个 CAN 帧。用反馈误差和稳定时间判断完成，禁止以 ACK 或发送结束判断。实现 STOP、BUSY、超时和完成后可继续下一条命令。上位机动作编排等待 DONE COMPLETED。执行至少 20 组保守姿态往返并记录七轴最终误差、到位时间差和遥测连续性。

## Phase 6：MIT 五次时间标度同步运动

### 目标

使用 250 Hz MIT 设定值实现七轴渐变速度和可量化的同步到达。

### 固件任务

- 完成五次时间标度和时长约束公式的纯函数单元测试。
- 以 4 ms 绝对周期生成七轴 `p_des/v_des`，`t_ff=0`。
- 逐轴从低 Kp/Kd 台架调参，参数版本化。
- 测量控制周期抖动、七帧发送偏斜、CAN 负载和跟随误差。
- 若进入 MIT 阶段，通过受控维护流程统一切换七个驱动器；去使能、驱动复位、重新自检和重新对齐后才可运动。

### 上位机同步任务

- UI 显示当前部署模式，不提供普通运行时切换按钮；维护入口独立、默认隐藏并要求重新对齐。
- 显示预计时长、实际时长、最大误差和同步到达差。
- 示波器展示目标预览、实测角和误差，来源标签明确。

### 验收

- 轨迹数学单元测试覆盖边界、零位移、速度/加速度约束和浮点异常。
- 100 组保守姿态运动无越限、无振荡、无 deadline miss。
- 250 Hz 控制周期的 p99/max 抖动和 CAN 负载有报告。
- 七轴起步和到位时间差达到阶段开始前签署的阈值；建议首轮目标 `<80 ms`，再根据机械系统实测收紧。
- 运动中所有反馈保持新鲜，数字孪生 50 Hz 连续更新。

### 阶段提示词

> 执行 Phase 6，先通过维护流程将七个驱动器统一切换到 MIT 并读取确认；驱动复位后清除 alignment，重新自检和对齐。按《03 达妙 CAN 与实时固件规范》以候选 250 Hz 实现五次时间标度：七轴共享 t0、T、s(u)，每轴输出 p_des 与 v_des，t_ff 固定 0。先做纯函数和 CAN 打包测试，再逐轴低增益联调，最后整组。记录 Kp/Kd 版本、控制周期 p99/max、七帧 TX 偏斜、CAN 负载、跟随误差和七轴到位时间差。上位机显示预计/实际时长和误差，不使用 UI 估算代替固件结果。

## Phase 7：故障恢复、压力和长稳

### 目标

证明系统在串口拥塞、CAN 异常、反馈丢失、驱动故障和长时间运行下可诊断、可恢复。

### 固件任务

- 完成反馈过期、bus-off、RX/TX overflow、控制周期超期和看门狗策略。
- 完成 RAM 日志、诊断快照和重启 `boot_id`。
- 做 8 小时静态遥测、2 小时保守循环运动和内存/栈水位测试。
- 对断上位机、重连和重复 request ID 做故障注入。

### 上位机同步任务

- 重连后重新握手和重建状态，不复用旧 in-flight 命令。
- boot_id 改变时清空目标执行状态并要求重新对齐。
- 故障页显示原始驱动码、关节、时间和恢复步骤。

### 验收

- 故障注入结果与状态机表一致，无错误成功提示。
- 8 小时无未解释的堆增长、栈溢出、死锁和计数器异常。
- UART 遥测积压只丢遥测，不延迟 STOP/DISABLE。
- 断线/重连后能继续查询并在满足条件后开始新命令。

### 阶段提示词

> 执行 Phase 7。建立可重复故障注入：拔掉单个 CAN 节点、制造反馈超时、模拟驱动错误、CAN bus-off、串口限速/断开、重复请求、坏 CRC 和控制任务压力。验证状态机、全部去使能/受控停止、事件、DONE 结果和恢复条件。运行 8 小时静态遥测与 2 小时保守动作循环，导出任务栈余量、队列高水位、deadline miss、CAN/UART 计数和 RAM 日志。同步验证上位机 boot_id 重建和重连流程。

## Phase 8：Aethor_robo 第二个七轴关节组接入

### 目标

不复制协议和业务代码，只增加第二套部署配置和上位机双会话能力；组装归属确认后再映射为左臂或右臂。

### 固件任务

- 保持同一固件代码和协议主版本。
- 为第二控制器分配独立 `controller_id`、`arm_id` 和版本化关节参数。
- 重做方向、参考位、限位、增益和阶段 1–7 的硬件相关验收。

### 上位机同步任务

- 同时维护两套 `RobotSessionSnapshot`，命令必须绑定明确 `controller_id/arm_id`。
- 控制台提供机械臂组选择；实体/幽灵模型、串口状态、命令状态和动作编排按组隔离。
- 禁止切换组时把上一组目标草稿发送给下一组。

### 验收

- 两控制器同时在线时遥测和命令不会串线。
- 任一组断开、故障或停止不污染另一组会话状态。
- 两组使用相同协议测试集，硬件参数和标定记录分别保存。

### 阶段提示词

## 2. 阶段提交规则

每个 Phase 的提交至少包含：

```text
phase(N): <可验证结果>

- firmware: <本阶段固件能力>
- protocol: <协议/契约变更或 unchanged>
- studio: <上位机同步状态>
- verification: <测试命令与结果>
- limitations: <仍未验证的限制>
```

协议不兼容修改不得混在普通修复提交中；必须同时更新本目录协议、测试向量、固件解析器和上位机适配器。
