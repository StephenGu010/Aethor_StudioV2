# 06 测试矩阵与交接模板

## 1. 测试层级

| 层级 | 环境 | 重点 |
|---|---|---|
| Host 单元测试 | PC 上编译纯 C/C++ | CRC、解析、CAN 编解码、坐标转换、插补、限位、状态机 |
| 固件集成测试 | STM32 控制板，无电机或 CAN 仿真 | FreeRTOS 任务、DMA、队列、快照、超时、看门狗 |
| 单电机台架 | 1 个 3519/3520，卸载或隔离 | 模式、反馈、单位、增益、停止、故障 |
| 七电机静态台架 | 7 个驱动，保持失能 | ID 映射、反馈、总线负载、温度和长稳 |
| 单轴装机测试 | 机械臂装配，其他轴保持 | 方向、参考位、限位和小角度动作 |
| 七轴装机测试 | 完整首组机械臂 | 同步运动、数字孪生、动作编排和故障恢复 |
| 上位机端到端 | Aethor Studio V2 + 网关 + 固件 | 请求关联、实时显示、断线重连和 UI 状态 |

所有通电运动测试应由具备机械和电气经验的人员在受控台架上执行，先低速度、小角度、单轴，再扩大到七轴。

## 2. 单元测试矩阵

| ID | 用例 | 期望 |
|---|---|---|

| P-002 | `REQ 1 GET_JPOS` | CRC `0x3223` |
| P-003 | `REQ 1 HELLO client=aethor-studio-v2 protocol=1` | CRC `0x1D7E` |
| P-004 | 最短合法请求 | 正确解析 |

| P-011 | 同 request ID 不同载荷 | `REQUEST_ID_CONFLICT` |
| P-012 | 未知可选响应键 | 上位机忽略并继续解析 |
| P-013 | 重复键、值含空格/`*`/`=`/CR/LF | `BAD_FRAME`，不同实现不得选择不同值 |

| P-015 | 完整快照只包含任意电机子集 | 固定七项数组配合 mask；缺失项不被解释为反馈 |
| P-016 | ID >7、重复/冲突 ID | 异常集合/冲突 mask 可见，受影响轴不更新 |
| P-015 | boot_id 或 session 变化 | 旧请求、心跳和 DONE 不再归属当前会话 |

| M-002 | 参考位 bias 计算 | 对齐后 q 等于 q_ref |
| M-003 | J1–J7 不同 bias | 无串轴 |

| M-010 | 反馈稳定窗口 | 所有轴连续满足才完成 |

### 2.4 状态机

对每个状态测试所有命令，确认允许表和错误码一致。重点路径：

- `BOOT → SELF_TEST → UNALIGNED → ALIGN → DISABLED/READY`。
- 未对齐时不能 ENABLE/MOVE。
- 模式只能在去使能时切换。
- 驱动模式维护导致任一驱动或 MCU 复位后，必须返回 UNALIGNED，旧 boot/session 请求全部失效。
- `MOVING → STOPPING → READY` 后可以继续下一次 MOVE。
- `MOVING → FAULT → DISABLED` 后必须显式清错和重新满足条件。
- DISABLE 重复调用幂等。
- 控制器重启后 alignment 和活动命令清空。

## 3. 台架测试矩阵

### 3.1 CAN 与反馈

| ID | 条件 | 采集 | 通过标准 |
|---|---|---|---|
| B-001 | 七电机失能、静态 30 min | CAN 负载、帧率、错误、反馈年龄 | 七轴持续更新，无错误/overflow |
| B-002 | 逐轴手动转动 | CAN ID、D0 ID、q/qd | 只更新对应 J，方向记录明确 |
| B-002A | 仅连接任意 1–6 个唯一 ID | presence 与模型对应，未连接链灰显，整组动作锁定 |
| B-002B | 接入 ID 8 或制造可观测 ID 冲突 | 明确告警且不驱动任何错误关节；诊断可导出 |
| B-003 | 250 Hz MIT 空载 | 平均/峰值负载、TX 偏斜 | 平均≤60%、峰值≤70% 或按实测调整周期 |
| B-004 | 失能后台轮询 + 高频 GET_JPOS | CAN TX 计数 | GET_JPOS 不增加后台轮询基线 |
| B-005 | 拔除一个反馈节点 | age、状态、事件 | 在阈值内检测并停止/失能 |
| B-006 | CAN bus-off | FDCAN 状态、日志、恢复 | 锁存故障，恢复策略有界 |
| B-007 | 停止上位机 HEARTBEAT | LINK_TIMEOUT、状态、使能掩码 | 1,000 ms 超时后 STOP_DISABLE |

### 3.2 角度对齐

每轴记录：

| 关节 | 参考角 deg | direction | 当前 p_motor rad | bias deg | +5° 实机方向 | +5° 最终反馈 | URDF 角 | 结论 |
|---|---:|---:|---:|---:|---|---:|---:|---|
| J1 | TBD | TBD | | | | | | |
| J2 | TBD | TBD | | | | | | |
| J3 | TBD | TBD | | | | | | |
| J4 | TBD | TBD | | | | | | |
| J5 | TBD | TBD | | | | | | |
| J6 | TBD | TBD | | | | | | |
| J7 | TBD | TBD | | | | | | |

角度统一的通过标准：上位机目标 `q_target_deg` 下发后，固件最终 `q_deg` 和 URDF 实体模型角均在该关节规定容差内；不存在额外的 360°、零偏、减速比或正负号修正。

### 3.3 同步运动

至少使用：单轴大位移、七轴等位移、七轴不等位移、部分零位移、往返动作和短距离动作。每次记录：

- request ID、模式、起点、目标、speed、计算时长。
- 每轴首次速度超过阈值的时刻。
- 每轴首次进入位置/速度容差并持续稳定的时刻。
- 最大跟随误差、最终误差、STOP/DONE 状态。
- 控制周期 p50/p95/p99/max、deadline miss。
- CAN 平均/峰值负载、TX 首末帧偏斜。

同步到达差定义为七轴稳定时刻最大值减最小值，而不是 CAN 帧发送时差。

### 3.4 上位机实时性

| 链路 | 指标 |
|---|---|
| 固件快照 | 250 Hz 构建，反馈有效性和 age 可观测 |
| 固件 TEL | 默认 50 Hz，frame_seq 连续性可统计 |
| C# 接收 | 解码率、CRC 错误、序号间隙、缓冲丢帧 |
| SignalR/IPC | 推送率、队列长度和 drop-old计数 |
| 浏览器 | 3D 实际刷新率、长任务、GPU/内存稳定性 |

测试机械臂连续运动 10 分钟，模型不得只在动作完成后跳变，也不得因 GET_JPOS、事件或终端显示而停更。

终端并发测试：让一个查询或人工帧故意不返回，随后连续发送诊断查询并发送 STOP。串口 writer 必须继续完成后续 transport write；未回复请求只在自己的 pending 项超时，不能占住全局写锁。记录各优先级队列等待时间、高水位、丢弃和 STOP 最坏排队时间。

## 4. 故障恢复测试

| 故障 | 注入方法 | 期望状态 | 恢复验证 |
|---|---|---|---|
| UART 拔出 | 运动/静止两种状态拔线 | 固件执行配置的断线策略；上位机离线 | 重连后 HELLO/GET_STATE/GET_JPOS |
| 错误 COM | 选择无设备或被占用端口 | 连接失败但可断开/重试 | 正确端口可重新连接 |
| 固件重启 | 手动复位 MCU | boot_id 变化，UNALIGNED | 上位机清空 in-flight 并要求对齐 |
| 单轴反馈丢失 | 断开某驱动 CAN | FAULT，活动命令 FAILED | 恢复 CAN、七轴新鲜、清错 |
| 驱动故障 | 供应商工具/受控条件注入 | 原始状态码保留并停止/失能 | 原因消失后 CLEAR_FAULT |
| UART TX 拥塞 | 限制 PC 读取或提高 TEL | 只丢遥测；STOP/DISABLE 优先 | 降低流率后恢复 |
| 重复 MOVE | ACK 丢失后重发同 request ID | 只执行一次 | 返回同一运动状态/结果 |
| 命令完成 | 连续发送两次合法 MOVE | 第一条 DONE 后门控释放 | 第二条正常执行，无需重启 |

## 5. 长稳与资源测试

- 8 小时：七电机失能、50 Hz 遥测、周期查询。
- 2 小时：保守姿态动作循环，包含停留和 STOP 恢复。
- 每 10 分钟采集任务栈余量、堆余量、队列高水位、控制周期 max、CAN/UART 计数和温度。
- FreeRTOS 栈溢出钩子、malloc failed 钩子和硬故障处理必须能记录最小诊断。
- 结束时所有计数器变化可解释；无堆持续下降、队列持续增长、遥测逐步降频或反馈年龄漂移。

## 9. CRC 固定测试向量

CRC 计算不含 CRC 前的空格和 `*XXXX`：

| ASCII 输入 | CRC-16/CCITT-FALSE |
|---|---:|
| `123456789` | `29B1` |
| `REQ 1 GET_JPOS` | `3223` |
| `REQ 1 HELLO client=aethor-studio-v2 protocol=1` | `1D7E` |
| `REQ 2 SET_STREAM rate_hz=50 fields=jpos,jvel,state,motor` | `11A2` |

线上完整帧示例：

```text
REQ 1 GET_JPOS *3223\n
REQ 1 HELLO client=aethor-studio-v2 protocol=1 *1D7E\n
REQ 2 SET_STREAM rate_hz=50 fields=jpos,jvel,state,motor *11A2\n
```

这些值已按 CRC-16/CCITT-FALSE 独立计算核对。实现时必须把同一向量放入固件 Host 测试和 C# codec 测试，不能只在文档中保留。
