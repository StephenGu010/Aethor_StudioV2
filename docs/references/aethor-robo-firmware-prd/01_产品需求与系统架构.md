# 01 产品需求与系统架构

## 1. 目标

首个固件版本控制一组七自由度机械臂，为 Aethor Studio V2 提供稳定的关节状态、整组关节角命令和运行诊断。上位机中的实体模型只使用实机反馈，幽灵模型只表示待下发目标；固件是电机状态、命令状态和运动完成状态的唯一事实来源。

系统只处理关节空间。上位机输入七个目标关节角，固件完成限位校验、统一时间标度、控制周期采样和七电机下发。固件不解析 URDF，不计算正逆运动学，也不生成笛卡尔路径。

## 2. 功能范围

### 2.1 首版必须具备

- 识别 7 个电机，核对 CAN ID、Master ID、控制模式和映射量程。
- 输出七轴位置、速度、扭矩、温度、驱动状态和反馈新鲜度。
- 支持整组使能、整组去使能、停止、清错和查询。
- 支持七轴关节参考位对齐，建立驱动位置与 URDF 关节角之间的确定映射。
- 支持位置速度模式和 MIT 模式，但按阶段分别验证；首个可运动版本先使用已冻结的全组模式，不提供运行中模式切换。
- 支持七轴统一起步、统一减速和同步到达。
- 支持持续遥测，机械臂运动期间模型仍连续更新。
- 支持带请求号的串口命令、异步事件和可关联的最终结果。
- 提供 CAN、UART、任务周期、队列水位和反馈超时诊断。

### 2.2 后续版本

- Aethor_robo 的第二个七自由度关节组复用同一固件分支，通过部署配置区分 `controller_id` 与 `arm_id`；当前首组尚未锁定为左臂或右臂。
- Aethor Studio V2 同时管理两个串口会话或由后端聚合两个控制器。
- 动作编排由上位机管理动作列表，固件仍只执行单段 `MOVE_JOINTS`，不在 MCU 中保存复杂程序。

### 2.3 不纳入本固件

- 逆运动学、雅可比、笛卡尔目标和末端拖拽。
- 动力学、重力补偿、阻抗、碰撞检测和自动避障。
- MoveIt、ROS、MATLAB、Simscape 协议。
- 机械臂动作脚本解释器和长期动作库。

## 3. 系统边界

```text
Aethor Studio V2 Frontend
        │  RobotGatewayV1
        ▼
C# Hardware Gateway（后续）
        │  aethor-arm-ascii-v1 / UART
        ▼
STM32H723 + FreeRTOS
  ├─ Protocol：解析、校验、响应、遥测
  ├─ Arm Domain：状态机、关节坐标、命令生命周期
  ├─ Motion：统一时间标度和设定值生成
  ├─ Motor Adapter：DM3520 MIT / POS_VEL 帧
  └─ BSP：FDCAN1、UART DMA、时钟、看门狗
        │  Classic CAN 1 Mbps
        ▼
DM3520-1EC × 7 ── DM-S3519-1EC × 7
```

职责划分：

| 层 | 拥有的数据与职责 |
|---|---|
| 前端 | 目标草稿、幽灵模型、图表、操作意图和展示布局 |
| C# 网关 | 串口独占、协议编码解码、命令超时、会话恢复和前端推送 |
| 固件 | 电机反馈、关节对齐、运动状态、命令执行、故障和实时控制 |
| 驱动器 | 电流环/速度环/位置环、编码器位置和驱动保护 |

前端不得根据按钮点击自行宣布使能、完成或停止；它只能显示固件返回的状态。固件不得依赖上位机轮询才能完成控制周期或故障处理。

## 4. 稳定标识和七轴映射

首组机械臂建议使用以下身份；`arm_id` 在机械装配归属未确定前使用中性名称：

| 字段 | 首组值 | 说明 |
|---|---|---|
| `product` | `aethor-robo` | 产品族 |
| `controller_id` | `aethor-arm-controller-01` | 控制器唯一标识 |
| `arm_id` | `arm-01` | 当前机械臂组 |
| `dof` | `7` | 固定七轴 |
| `protocol` | `aethor-arm-ascii-v1` | 候选上位机协议；固件实现与共享测试向量通过后冻结 |

电机映射冻结如下：

| 关节 | 索引 | 驱动接收 ID | 反馈 Master ID | 控制帧 ID：MIT | 控制帧 ID：POS_VEL |
|---|---:|---:|---:|---:|---:|
| J1 | 0 | `0x001` | `0x00B`（11） | `0x001` | `0x101` |
| J2 | 1 | `0x002` | `0x00C`（12） | `0x002` | `0x102` |
| J3 | 2 | `0x003` | `0x00D`（13） | `0x003` | `0x103` |
| J4 | 3 | `0x004` | `0x00E`（14） | `0x004` | `0x104` |
| J5 | 4 | `0x005` | `0x00F`（15） | `0x005` | `0x105` |
| J6 | 5 | `0x006` | `0x010`（16） | `0x006` | `0x106` |
| J7 | 6 | `0x007` | `0x011`（17） | `0x007` | `0x107` |

启动时必须逐项核对驱动器寄存器中的接收 ID、反馈 ID 和控制模式。发现重复 ID、反馈 ID 不匹配、七轴模式不一致或任意电机缺失时进入 `FAULT`，禁止整组使能。上表是部署目标，不代表当前七个驱动已实测写入。

## 5. 关节坐标与参考位

### 5.1 三套角度的定义

系统中同时存在三套坐标，必须显式转换：

1. `p_motor_rad[i]`：DM3520 反馈的减速后输出轴位置，单位 rad。供应商手册说明驱动器上电后位置固定为 `0 rad`。
2. `q_joint_deg[i]`：固件对外发布的机械臂关节角，单位 deg，是上位机、滑条和 URDF 的统一角度。
3. `q_urdf_rad[i]`：Three.js/URDF 使用的弧度，等于 `q_joint_deg × π / 180`。

转换关系：

```text
q_joint_deg[i] = direction[i] × rad_to_deg(p_motor_rad[i]) + zero_bias_deg[i]
p_target_rad[i] = deg_to_rad(direction[i] × (q_target_deg[i] - zero_bias_deg[i]))
qdot_joint_deg_s[i] = direction[i] × rad_to_deg(v_motor_rad_s[i])
```

`direction[i]` 只能为 `+1` 或 `-1`。`zero_bias_deg[i]` 是本次上电会话的对齐结果。

### 5.2 每次上电的对齐流程

因为驱动器位置在上电后从零开始，仅靠反馈不能恢复机械臂绝对姿态。首版不虚构回零传感器，采用明确的参考位对齐：

1. 上电后固件读取七轴反馈，状态为 `UNALIGNED`，允许查询，不允许运动。
2. 操作者将机械臂放到文档化的机械参考姿态。
3. 上位机发送 `ALIGN_REFERENCE`，携带该姿态对应的七个 `q_ref_deg`。
4. 固件保存当前 `p_motor_rad`，计算 `zero_bias_deg`。
5. 固件立即回算 `q_joint_deg`，必须与 `q_ref_deg` 在容差内一致，随后进入 `DISABLED`；操作者仍需单独执行整组使能。

计算式：

```text
zero_bias_deg[i] = q_ref_deg[i] - direction[i] × rad_to_deg(p_motor_rad[i])
```

这是一种“已知机械姿态 + 会话偏置”的参考建立方法，不等同于驱动器 `保存位置零点`。如果机构有抱闸、绝对编码器、限位开关或其他可信参考源，应在 Phase 0 改为相应的对齐策略并同步更新协议；在来源未确认前，不允许自动假设机械臂已处于参考姿态。

对齐值默认只在 RAM 中保存，重启、看门狗复位或重新上电后失效。只有增加可靠绝对零位来源后，才允许讨论持久化。

### 5.3 Profile 对齐要求

- 固件和上位机 Profile 中的 J1–J7 顺序、方向、软限位必须完全一致。
- 上位机 Profile 当前若使用占位限位，不得据此开放实机运动。
- `GET_JPOS` 返回的就是 `q_joint_deg`，不是原始电机 rad。
- 数字孪生实体模型使用 `q_joint_deg`；幽灵模型的目标也使用同一角度。
- 上位机下发前不再自行添加零偏或反向，转换只在固件完成，避免重复修正。

## 6. 控制器状态机

```text
BOOT → SELF_TEST → UNALIGNED → DISABLED → ENABLING → READY → MOVING
                         ▲           ▲                   │       │
                         │           └───────────────────┴──→ STOPPING
                         │                                      │
                         └──────────── FAULT ←──────────────────┘
```

状态定义：

| 状态 | 含义 | 允许的主要命令 |
|---|---|---|
| `BOOT` | HAL/RTOS 尚未完成启动 | 无 |
| `SELF_TEST` | 检查配置、CAN、七电机和驱动参数 | `GET_*` |
| `UNALIGNED` | 反馈有效但本次会话未建立关节参考 | `GET_*`、`ALIGN_REFERENCE`、`DISABLE` |
| `DISABLED` | 电机已去使能；对齐可能仍有效 | `GET_*`、`ENABLE`、`ALIGN_REFERENCE`、`CLEAR_FAULT` |
| `ENABLING` | 正在逐个使能并等待七轴反馈确认 | `STOP`、`DISABLE`、`GET_*` |
| `READY` | 七电机使能、反馈新鲜、可接收运动 | `MOVE_JOINTS`、`STOP`、`DISABLE`、`GET_*` |
| `MOVING` | 正在执行一段整组运动 | `STOP`、`DISABLE`、`GET_*`；新的 MOVE 返回 `BUSY` |
| `STOPPING` | 正在减速停止或执行快速停机序列 | `DISABLE`、`GET_*` |
| `FAULT` | 驱动、CAN、配置或实时性故障 | `GET_*`、`STOP`、`DISABLE`、条件满足后的 `CLEAR_FAULT` |

状态转换只能由 Arm Domain 完成。UART 解析器、电机回调和前端不能直接改全局状态。驱动器参数写入、控制模式改变、驱动器复位、MCU 复位或电源重启都会使当前对齐失效，状态必须重新进入 `UNALIGNED`；正常的串口断开若 MCU 与电机未重启，只执行通信看门狗动作，不应凭空改写角度参考。

## 7. 命令生命周期

每条会改变状态的命令均携带 `request_id`。固件返回：

1. `ACK`：语法、状态和参数已校验，命令已被固件接管。
2. 一个或多个 `EVT`：异步状态变化，例如开始运动、停止中、故障。
3. `DONE`：命令达到终态，包含 `COMPLETED/STOPPED/FAILED/CANCELLED`。

接收 `ACK` 不等于机械动作完成。运动完成条件以七轴反馈误差和稳定时间为准，而不是发送完最后一帧，也不是裸字符串 `ok`。

同一 `request_id` 重复到达时：

- 若原请求仍在执行，返回同一命令的当前状态，不重复执行。
- 若已经结束，在短期结果缓存中返回原最终结果；查询类请求只复用原响应，不在重复请求上重新读取可变快照。
- 若请求号相同但载荷不同，返回 `REQUEST_ID_CONFLICT`。

固件至少保留最近 32 条终态结果，或保留 60 秒，先到者淘汰。

## 8. 建议固件目录

CubeMX 生成代码保持在 `Core/`、`Drivers/`、`Middlewares/`；业务代码放在独立目录，避免下次生成时被覆盖：

```text
Firmware/
├─ AethorRobo.ioc
├─ MDK-ARM/
├─ Core/
│  ├─ Inc/
│  └─ Src/
├─ Drivers/
├─ Middlewares/Third_Party/FreeRTOS/
├─ App/
│  ├─ Config/          # arm_config、版本、部署身份
│  ├─ Protocol/        # ASCII 分帧、解析、编码、命令表
│  ├─ Arm/             # 状态机、关节坐标、命令生命周期
│  ├─ Motion/          # 五次时间标度、限位和完成判定
│  ├─ Motor/           # DmMotorTransport、帧编码解码
│  ├─ Telemetry/       # 快照、事件、统计和日志
│  └─ Platform/        # UART DMA、CAN、时钟、看门狗适配
└─ Tests/
   ├─ Host/            # 可在 PC 运行的纯 C 单元测试
   └─ Bench/           # 台架步骤、采集结果和测试脚本
```

依赖方向固定为：`Protocol → Arm → Motion → Motor → Platform`。反馈方向通过只读快照和事件上送，不允许 Platform 直接调用上层 UI 协议。

## 9. 配置数据结构

每个关节至少配置：

```c
typedef struct {
    uint8_t joint_index;       // 0..6
    uint16_t motor_can_id;     // 1..7
    uint16_t master_id;        // 11..17
    int8_t direction;          // +1 or -1
    float q_min_deg;
    float q_max_deg;
    float v_limit_deg_s;
    float a_limit_deg_s2;
    float position_tolerance_deg;
    float velocity_tolerance_deg_s;
    float mit_kp;
    float mit_kd;
    float torque_ff_nm;
    float pmax_rad;
    float vmax_rad_s;
    float tmax_nm;
} JointConfig;
```

启动校验必须拒绝：重复 CAN ID、重复 Master ID、关节索引缺失、方向为零、下限不小于上限、非有限浮点数、控制增益超出供应商范围、映射量程与驱动寄存器不一致。

## 10. 关键验收结果

首组机械臂完成时应满足：

- 手动缓慢转动任意允许转动的轴，J1–J7 对应模型关节方向和角度一致。
- 机械臂运动期间，50 Hz 遥测持续输出，没有因为查询或命令 ACK 中断。
- 幽灵模型七个角度经固件转换后，实机最终反馈回到同一组 `q_joint_deg`。
- 七轴使用共同的时间标度，起步和结束时间差有可量化记录。
- 断开串口不会破坏 MCU 实时控制；上位机重连后可查询当前真实状态。
- 任一电机反馈过期、驱动故障、CAN bus-off 或控制周期严重超期都会结束当前命令并产生可定位事件。
