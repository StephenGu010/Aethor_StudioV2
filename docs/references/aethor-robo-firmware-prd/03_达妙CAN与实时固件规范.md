# 03 达妙 CAN 与实时固件规范

## 1. 适用硬件和协议基线

本章面向 DM-MC-Board02、STM32H723VGT6、DM-S3519-1EC 与 DM3520-1EC。供应商资料确认：

- 电机控制使用 CAN 标准帧；DM3520 默认 1 Mbps 且可改，项目部署必须核对驱动器与 CubeMX nominal bit timing 后冻结。
- DM3520 支持 MIT、位置速度和速度等模式。
- 输出轴位置和速度单位分别为 rad、rad/s，扭矩单位为 Nm。
- 驱动器上电后位置固定为 `0 rad`，所以机械臂每次上电仍需关节参考位对齐。
- 反馈帧在三种控制模式下采用相同格式。

本项目只使用 MIT 与位置速度模式。CubeMX 中虽然配置的是 FDCAN 外设，但总线按 Classic CAN 使用：标准 ID、最大 8 字节载荷，不启用 CAN FD 数据段。

## 2. 七电机 CAN 配置

| 关节 | 驱动接收 ID `ESC_ID` | 反馈 ID `MST_ID` | MIT 控制 ID | 位置速度控制 ID |
|---|---:|---:|---:|---:|
| J1 | 1 | 11 | `0x001` | `0x101` |
| J2 | 2 | 12 | `0x002` | `0x102` |
| J3 | 3 | 13 | `0x003` | `0x103` |
| J4 | 4 | 14 | `0x004` | `0x104` |
| J5 | 5 | 15 | `0x005` | `0x105` |
| J6 | 6 | 16 | `0x006` | `0x106` |
| J7 | 7 | 17 | `0x007` | `0x107` |

`MST_ID` 是驱动反馈帧 ID，不是给电机发控制命令的 ID。FDCAN1 过滤器只接收 `0x00B–0x011` 和联调期必要的参数读写响应；发布版本不能使用全接收过滤器长期运行。DM3520 对控制帧匹配只校验 CANID 低 8 位，项目仍统一使用标准 11 位 ID，并在配置阶段拒绝任何会产生低 8 位冲突的 ID。

表格定义的是完整七轴部署目标，不是调试发现态的“必须同时在线”条件。台架允许接入任意数量、任意接线顺序的驱动；控制器始终按反馈 D0 的 `motor_id` 及已核对的 `MST_ID` 交叉识别，`motor_id 1…7` 固定映射到 J1…J7。接收先后顺序和物理插线顺序不能改变关节编号。ID 大于 7、重复 ID 或低 8 位冲突只进入诊断，不得自动改映射、取模或占用空缺关节。

### 2.1 启动核对

在首次安装或部署配置变更后，固件对当前实际发现的驱动逐个读取并记录；缺失槽保留为 absent，不因某个电机缺失中止其他槽的诊断：

- `RID_MST_ID`：反馈 ID。
- `RID_ESC_ID`：接收 ID。
- `RID_CMODE`：控制模式。
- `RID_PMAX/VMAX/TMAX`：MIT 映射范围。
- `RID_ACC/DEC/MAX_SPD`：驱动位置速度模式参数。
- 驱动软件版本与 CAN 波特率配置。

参数读取只能在去使能且无运动时进行。运行周期中不得穿插寄存器扫描。供应商 H7 示例的寄存器 RID 值必须通过单电机读回与 V1.1/V1.4 文档交叉验证后进入项目常量，不能只凭示例枚举冻结。

启动结束生成 `present_mask/conflict_mask/unexpected_ids`。调试发现态允许不完整 mask 并向上位机持续发布已识别轴；整组使能、同步运动和动作编排要求 1–7 全部唯一存在且配置摘要一致。对完全相同 CAN ID 的两个驱动，经典 CAN 可能表现为仲裁后数据冲突、错误帧或不可区分响应，因此只能报告 `DUPLICATE_ID_SUSPECTED`，不能声称精确识别了重复数量。

## 3. DM3520 控制帧

以下均为标准帧，字节编号 `D[0]..D[7]`。

### 3.1 MIT 模式

帧 ID：`ESC_ID + 0x000`，DLC 8。

| 字节 | 位域 |
|---|---|
| D0 | `p_des[15:8]` |
| D1 | `p_des[7:0]` |
| D2 | `v_des[11:4]` |
| D3 | `v_des[3:0] << 4 | kp[11:8]` |
| D4 | `kp[7:0]` |
| D5 | `kd[11:4]` |
| D6 | `kd[3:0] << 4 | t_ff[11:8]` |
| D7 | `t_ff[7:0]` |

线性映射：

```c
uint32_t float_to_uint(float x, float min, float max, uint8_t bits) {
    x = clamp(x, min, max);
    return (uint32_t)((x - min) * ((1u << bits) - 1u) / (max - min));
}

float uint_to_float(uint32_t x, float min, float max, uint8_t bits) {
    return ((float)x) * (max - min) / ((1u << bits) - 1u) + min;
}
```

映射位宽与范围：

| 量 | 位宽 | 范围来源 |
|---|---:|---|
| `p_des` | 16 | `[-PMAX, +PMAX]`，读取实际驱动寄存器 |
| `v_des` | 12 | `[-VMAX, +VMAX]`，读取实际驱动寄存器 |
| `kp` | 12 | `[0, 500]` |
| `kd` | 12 | `[0, 5]` |
| `t_ff` | 12 | `[-TMAX, +TMAX]`，读取实际驱动寄存器 |

供应商手册示例使用 `PMAX=12.5 rad`、`VMAX=45 rad/s`、`TMAX=18 Nm`，但这些值可配置且不是本机械臂的批准参数。固件不得只用示例常量；启动读取值必须与部署配置一致，否则进入 `CONFIG_MISMATCH`。

首轮整机联调中 `t_ff=0`，不做动力学前馈。`kp/kd` 每轴独立配置，并从低值逐步验证。位置控制时 `kd` 不得设为 0。

### 3.2 位置速度模式

帧 ID：`ESC_ID + 0x100`，DLC 8。

| 字节 | 内容 |
|---|---|
| D0–D3 | `p_des`，IEEE-754 float32，小端，单位 rad |
| D4–D7 | `v_des`，IEEE-754 float32，小端，单位 rad/s |

`v_des` 是运动过程中的最大绝对速度约束。发送前必须检查浮点数有限、端序正确、目标在软限位内。

该模式适合单电机和整组基础联调。驱动器内部位置/速度环和 ACC/DEC 会影响实际到达时间；因此“七轴精确统一时间标度”的正式验收使用 MIT 模式。若位置速度模式也要声明同步到达，必须单独记录实测到达时间差，不能仅凭同时发送命令判断。

### 3.3 使能、失能和清错

帧 ID 等于当前驱动控制模式对应 ID（MIT 为 `CANID`，位置速度为 `0x100+CANID`），DLC 8：

| 操作 | D0–D6 | D7 |
|---|---|---|
| 使能 | `FF FF FF FF FF FF FF` | `FC` |
| 失能 | `FF FF FF FF FF FF FF` | `FD` |
| 保存位置零点 | `FF FF FF FF FF FF FF` | `FE` |
| 清除错误 | `FF FF FF FF FF FF FF` | `FB` |

本项目首版不调用“保存位置零点”：驱动器上电位置语义和机械臂绝对参考不是同一概念。机械关节对齐由固件会话偏置完成。

使能/失能/清错必须结合反馈状态确认。`HAL_FDCAN_AddMessageToTxFifoQ()` 成功只表示进入控制器发送队列，不表示驱动已执行。

## 4. 反馈帧

反馈标准帧 ID 为该电机的 `MST_ID`，DLC 8：

| 字节 | 位域 |
|---|---|
| D0 | `motor_id | error_state << 4`；本项目 ID 1–7 可用低 4 位解析 |
| D1 | `position[15:8]` |
| D2 | `position[7:0]` |
| D3 | `velocity[11:4]` |
| D4 | `velocity[3:0] << 4 | torque[11:8]` |
| D5 | `torque[7:0]` |
| D6 | MOS 平均温度，°C |
| D7 | 电机绕组平均温度，°C |

位置、速度、扭矩分别按 16、12、12 位用实际 `PMAX/VMAX/TMAX` 反映射。D0 中的 `motor_id` 是关节槽主键，反馈帧 CAN ID/MST_ID 是身份交叉校验。`motor_id` 不在 1…7 时记录 `MOTOR_ID_OUT_OF_RANGE`；同一 ID 出现在多个 MST_ID、与部署映射不一致或存在低 8 位冲突时记录 `DUPLICATE_ID_SUSPECTED/FEEDBACK_ID_MISMATCH`，并拒绝更新受影响槽的有效快照。

驱动状态码：

| 原始值 | 含义 | 固件处理 |
|---:|---|---|
| `0x0` | 失能 | 更新状态；若运动中则故障终止 |
| `0x1` | 使能 | 正常 |
| `0x5` | 读取传感器错误 | 故障、停止、去使能 |
| `0x6` | 读取电机参数错误 | 故障、禁止使能 |
| `0x8` | 过压 | 故障、停止、去使能 |
| `0x9` | 欠压 | 故障、停止、去使能 |
| `0xA` | 过电流 | 故障、立即去使能 |
| `0xB` | MOS 过温 | 故障、立即去使能 |
| `0xC` | 电机线圈过温 | 故障、立即去使能 |
| `0xD` | 通讯丢失 | 故障、立即去使能 |
| `0xE` | 过载 | 故障、停止、去使能 |

未知非零值统一映射为 `MOTOR_FAULT_UNKNOWN`，保留原始值。

## 5. CAN 总线调度

### 5.1 反馈获取策略

供应商 V1.1 手册说明反馈是问询式：驱动器收到低 8 位与 CANID 匹配的帧后返回当前状态。供应商 H7 示例还提供显式控制反馈查询帧：标准 ID `0x7FF`、DLC 4，载荷为：

| 字节 | 内容 |
|---|---|
| D0 | 目标 `ESC_ID[7:0]` |
| D1 | 目标 `ESC_ID[10:8]` |
| D2 | `0xCC` |
| D3 | `0x00` |

该查询帧必须先在 Phase 1 对实际 DM3520 固件验证。验证通过后采用以下策略：

- MIT 已使能：250 Hz 控制帧本身产生反馈，不额外轮询。
- POS_VEL 策略 A：目标帧只发送一次，驱动器内部仍在运动，因此必须继续以平均每轴 50 Hz 均匀轮转发送 `0x7FF` 查询；这是运动期间数字孪生连续更新的必要条件。
- `UNALIGNED/DISABLED` 或 POS_VEL 空闲：后台轮询器按平均每轴 50 Hz 均匀轮转发送 `0x7FF` 查询，维持手动转轴和数字孪生同步。
- POS_VEL 策略 B：若已通过台架验证并以候选 250 Hz 连续发送设定值，则控制帧产生反馈，不再额外轮询；必须证明驱动内部梯形加减速不会因持续更新目标而反复重置。
- 参数读取：仅在去使能的显式诊断窗口执行，与状态轮询互斥。
- `GET_JPOS`：永远只读已发布快照，不直接产生任何 CAN 帧。

如果实机固件不支持 `0x7FF/0xCC` 查询，Phase 1 必须记录替代的供应商确认方式；在此之前不得通过重复使能帧或伪控制帧获取静态反馈。

所有控制帧、反馈查询和参数读写都进入同一个 CAN 调度器：整组控制帧优先级最高，周期反馈查询其次，参数读写最低且只在去使能诊断窗口开放。UART 命令处理器不得直接调用 FDCAN 发送函数。

### 5.2 周期选择

MIT 首轮候选控制周期为 4 ms，即 250 Hz；它是经 Classic CAN 带宽预算得到的设计起点，不是供应商保证值。上位机聚合遥测候选默认 50 Hz。

依据：7 条控制帧通常引发 7 条反馈帧，每个周期约 14 条 8 字节标准帧。在 1 Mbps 下，按每帧约 111–135 bit 估算：

```text
14 × 250 × 111 bit ≈ 0.389 Mbps
14 × 250 × 135 bit ≈ 0.473 Mbps
```

加上仲裁、误码重发和诊断流量后，250 Hz 仍有合理余量。500 Hz 会使估算负载达到约 78%–95%，不适合作为七电机 Classic CAN 的初始设计点。

Phase 1 必须先测出“每条控制/查询帧产生几条反馈”的真实行为。最终发布前使用 CAN 分析仪实测：平均负载目标不高于 60%，持续峰值不高于 70%，无错误帧和 TX FIFO 持续积压。若实测帧行为与假设不同，以实测下调控制率，不能牺牲故障反馈。

### 5.3 每周期发送

- `ArmControlTask` 每 4 ms 生成同一逻辑时刻的七轴设定值。
- 七帧按 J1→J7 固定顺序放入单生产者 CAN TX 环形队列。
- 入队前检查至少有 7 个空槽；不能只入队部分关节。
- FDCAN TX 中断只负责从队列补充硬件 FIFO。
- 记录首帧与第七帧实际发送完成时间差，台架目标先定为 `<1.5 ms`，随后以测量值收敛。
- 运动过程中不执行参数读写或手工 CAN 透传。

Classic CAN 无法真正同时广播七个独立位置。固件的“同步”指七轴共享同一轨迹时间基准，CAN 帧发送偏斜受控且最终到达满足验收容差。

### 5.4 接收

- FDCAN RX ISR 读取硬件 FIFO 并写入 32 项原始帧环形缓冲，随后通知 `CanRxTask`。
- ISR 不做浮点解码、日志格式化、串口发送或状态机转换。
- `CanRxTask` 每次唤醒最多处理一个有界批次，解码后更新对应电机结构和时间戳。
- RX 环溢出、FDCAN FIFO overflow、bus-off 均设置锁存故障标志，由 `ArmControlTask` 在下一周期执行停机状态转换。

## 6. 同步关节运动

### 6.1 统一五次时间标度

MIT 模式使用统一的五次时间标度，让七轴同一时刻起步、同一时刻速度归零：

```text
u = clamp((t - t0) / T, 0, 1)
s(u)  = 10u³ - 15u⁴ + 6u⁵
s'(u) = 30u² - 60u³ + 30u⁴
s''(u)= 60u - 180u² + 120u³

q_i(t)  = q0_i + Δq_i × s(u)
qd_i(t) = Δq_i × s'(u) / T
```

该曲线起点和终点的速度、加速度均为零，满足“渐变速度”，但它仍是关节插值，不是笛卡尔路径规划。

### 6.2 运动时长

五次时间标度的最大一阶导数为 `1.875`，最大二阶导数绝对值约为 `5.7735`。对每个非零位移关节：

```text
v_eff_i = speed × v_limit_i
a_eff_i = speed² × a_limit_i

T_vel_i = 1.875 × abs(Δq_i) / v_eff_i
T_acc_i = sqrt(5.7735 × abs(Δq_i) / a_eff_i)
T = max(T_min, max_i(T_vel_i, T_acc_i))
```

角度、速度和加速度可以统一用 deg 制计算 T，发送驱动前再转换为 rad。`speed` 取 `0.01–1.00`；用 `speed²` 缩放加速度可保持仅做时间拉伸时的曲线一致性。

### 6.3 每周期 MIT 设定值

- `p_des` 使用 `q_i(t)` 经方向和零偏反算得到的驱动 rad。
- `v_des` 使用 `qd_i(t)` 经方向换算得到的 rad/s。
- `kp/kd` 使用每轴已经台架验证的参数。
- `t_ff=0`。
- 最后一周期显式发送目标位置、零速度，并进入 `SETTLING`。

### 6.4 位置速度模式

位置速度模式首版支持两种策略，默认先实现策略 A：

- A：一次发送最终 `p_des`，按各轴位移和共同期望时长计算 `v_des_i`，由驱动内部 ACC/DEC 完成梯形速度。这是低风险联调路径，但到达同步性依赖驱动参数。
- B：以 250 Hz 发送五次时间标度的中间 `p_des` 和受限 `v_des`。只有台架证明驱动内部级联能够稳定跟踪且没有振荡后才能启用。

位置速度模式不得和 MIT 模式在同一动作中混用。模式切换必须先整组去使能。

### 6.5 完成判定

最后设定值发送完成不等于运动完成。所有关节必须同时满足：

```text
abs(q_target_i - q_feedback_i) <= position_tolerance_i
abs(qd_feedback_i) <= velocity_tolerance_i
feedback_valid_i == true
motor_fault_i == 0
```

并连续保持 `settle_ms` 后才发送 `DONE COMPLETED`。建议初始配置 `settle_ms=200 ms`，位置和速度容差通过实机测试收敛。

超时时，命令进入 `FAILED reason=FOLLOWING_ERROR/TIMEOUT`，执行受控停止；若反馈无效则立即去使能。不能只因上位机未收到某个队列号就把机械结果视为失败。

## 7. FreeRTOS 任务设计

优先级数值仅表示相对关系，落地时按当前 FreeRTOS 配置映射：

| 任务 | 周期/触发 | 相对优先级 | 责任 |
|---|---|---:|---|
| `ArmControlTask` | 4 ms 绝对周期 | 最高 | 唯一状态机所有者、轨迹采样、限位、完成判定、CAN 整组入队 |
| `CanRxTask` | RX 通知 | 很高 | 有界解码反馈、更新时间戳和错误标志 |
| `UartTxTask` | 队列通知 | 高 | 响应/事件/遥测分级发送，驱动 UART DMA |
| `ProtocolTask` | UART RX 通知 | 中 | 分帧、CRC、解析、语义校验，投递命令 |
| `TelemetryTask` | 20 ms 默认 | 中低 | 从发布快照生成 TEL，不直接读电机可变结构 |
| `DiagnosticsTask` | 100 ms/1 s | 低 | 汇总周期、队列和总线指标，喂业务健康状态 |

硬件看门狗由一个健康门控函数喂养：只有控制任务按期运行、CAN RX 未锁死且关键队列没有永久堵塞时才能刷新。任务优先级、栈大小、tick rate 和中断优先级必须从现有 CubeMX/FreeRTOS 配置测量后冻结，本文只规定相对所有权。

### 7.1 资源所有权

- `ArmControlTask`：控制器状态、活动命令、轨迹对象和 CAN 控制帧生产权。
- `CanRxTask`：每电机最新原始反馈的写权限。
- `TelemetryTask/ProtocolTask`：只读取不可变快照。
- `UartTxTask`：UART TX DMA 唯一所有者。
- UART RX ISR/FDCAN ISR：只写各自原始环形缓冲和通知任务。

任务启动后不进行动态内存分配。FreeRTOS 任务、队列、定时器和缓冲使用静态分配。

### 7.2 建议有界容量

| 资源 | 初始容量 | 满载策略 |
|---|---:|---|
| CAN RX raw ring | 32 帧 | 锁存故障，停止运动 |
| CAN TX ring | 32 帧 | 整组 7 帧不能原子入队则故障 |
| 业务命令队列 | 8 条 | 返回 `BUSY/TX_CONGESTED`；STOP 使用独立高优先级槽 |
| UART 高优先级 TX | 16 帧 | 不覆盖，记录故障 |
| UART 查询 TX | 16 帧 | 返回拥塞诊断 |
| UART 遥测 TX | 4 帧 | 丢弃最旧遥测，保留最新 |
| 事件日志 RAM ring | 256 条 | 覆盖最旧并累计覆盖计数 |
| 近期命令结果 | 32 条 | TTL/环形淘汰 |

容量需用运行期高水位指标验证，不能无限扩容掩盖拥塞。

## 8. 反馈快照与线程一致性

每个电机反馈包含原始帧、解码值、`rx_timestamp_us`、递增代数和有效标志。`CanRxTask` 更新后，`ArmControlTask` 在每个周期构造一个七轴一致性快照：

```c
typedef struct {
    uint64_t t_us;
    uint32_t generation;
    float q_deg[7];
    float qd_deg_s[7];
    float tau_nm[7];
    uint16_t age_ms[7];
    uint8_t present_mask;
    uint8_t valid_mask;
    uint8_t enabled_mask;
    uint8_t conflict_mask;
    uint8_t unexpected_id_count;
    uint8_t unexpected_id[8];
    uint8_t fault[7];
} JointSnapshot;
```

发布采用双缓冲或 seqlock，读者永远拿到完整的一代数据。`GET_JPOS`、遥测和运动完成判定都基于该快照；禁止各自直接读七个正在变化的 `motor[]` 元素。

完整发布快照每代都明确重建 presence；不能把“本周期未收到”直接等同为永久缺失，而应结合已发现身份与反馈年龄。只有 `present & valid & !conflict` 的槽可以更新上位机实体关节；任一上游关节不可信时，数字孪生应把该关节及其下游链标为姿态不完整。

初始反馈阈值建议：

- 候选 `age > 20 ms`：标记 warning。
- 候选运动中 `age > 40 ms`：该轴无效并触发停止/去使能。
- 非运动状态阈值可稍宽，但禁止在反馈不新鲜时使能或开始动作。

阈值须根据实测控制周期、反馈帧周期和尾延迟冻结；未冻结前不开放整组使能。

## 9. 故障与恢复

| 故障 | 检测 | 响应 | 恢复 |
|---|---|---|---|
| 单轴反馈超时 | 快照年龄 | 终止动作；无法受控停止时去使能全部 | CAN 恢复、七轴新鲜、人工清错 |
| 驱动过流/过温/过载 | 反馈状态码 | 立即停止普通下发并全部去使能 | 原因消失后显式清错 |
| CAN bus-off | FDCAN 协议状态/中断 | 全部去使能意图、锁存 FAULT、记录寄存器 | 有界恢复一次；失败需重启/检修 |
| CAN RX overflow | 硬件或软件计数 | 锁存 FAULT | 排查负载后重启会话 |
| 控制周期超期 | 单调时钟测量 | 单次警告，连续/严重超期停机 | 导出诊断，修复资源争用 |
| UART 拥塞 | TX 队列水位 | 先丢遥测，不影响控制；高优先级堵塞则 FAULT | 断开/重连并降低遥测率 |
| 上位机断开 | 1,000 ms HEARTBEAT 超时 | 活动动作受控停止，随后整组去使能；反馈无效则快速去使能 | 重连握手、查询真实状态后人工重新使能 |
| 配置不一致 | 启动寄存器核对 | 禁止使能 | 修正部署配置/驱动参数 |

首轮实验配置锁定为 `STOP_DISABLE`。后续若改变断线策略，必须修改部署配置版本、`GET_INFO` 能力字段、故障测试和上位机文案，不能只修改固件内部常量。

## 10. 诊断指标与日志

必须提供：

- `control_period_last/min/max_us`、deadline miss 次数和连续 miss 次数。
- 每周期第一帧到第七帧的 TX 时间差。
- CAN TX/RX 帧数、错误帧、重发、bus-off、FIFO overflow 和队列高水位。
- 每轴反馈年龄的 current/max。
- UART RX CRC/格式/溢出，TX 各优先级队列高水位，遥测丢弃数。
- 活动请求号、运动阶段、预计/实际时长、最大跟随误差。
- 启动时七个驱动器的 ID、模式、PMAX/VMAX/TMAX 和版本摘要。
- 当前 `present/valid/conflict` mask、异常 ID 集合、身份不匹配次数和疑似重复 ID 证据来源。

结构化 RAM 日志项至少包含：

```text
t_us, event_id, severity, controller_state, request_id,
joint, motor_id, value0, value1, raw_code
```

事件 ID 建议分段：`1000` 启动/配置、`2000` 串口协议、`3000` CAN、`4000` 电机、`5000` 运动、`6000` 状态/故障。日志不得在控制任务中格式化为长文本。

## 11. 编码要求

- 所有外部输入先检查长度、枚举、有限浮点和范围，再改变状态。
- CAN 编解码使用显式移位或 `memcpy`；禁止违反严格别名规则的指针强转。
- float32 小端编码必须有固定测试向量。
- 时间计算使用单调 64 位微秒时钟，正确处理底层定时器回绕。
- 运动计算使用 float 或 double 的选择应通过 H723 周期测量；发布构建禁止在实时路径打印。
- CubeMX 重新生成后，`App/` 业务代码和接口不能被覆盖。
- 供应商示例只作为帧参考，不直接复制其单电机全局变量、阻塞发送和固定映射参数结构。
