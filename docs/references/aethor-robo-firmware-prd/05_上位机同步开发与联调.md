# 05 Aethor Studio V2 同步开发与联调

## 1. 对接目标

Aethor Studio V2 不直接理解 DM3520 CAN 帧。前端仍面向 `RobotGatewayV1`，C# 硬件网关独占串口并实现 `aethor-arm-ascii-v1`。这样固件更换 UART、未来增加第二个控制器或协议升级时，3D、示波、动作编排和设备页面不需要直接处理串口细节。

```text
React UI
  │ RobotGatewayV1：业务命令和遥测
  ▼
C# Gateway
  ├─ SerialPortOwner：端口枚举、打开、关闭、生命周期
  ├─ AethorArmAsciiV1Codec：CRC、帧解析和编码
  ├─ CommandDispatcher：请求号、超时、重试和终态
  ├─ TelemetryHub：最新快照、有界缓冲和 SignalR 推送
  └─ SessionRegistry：controller_id / arm_id 会话
  │ UART
  ▼
七轴固件
```

前端、C# 和固件共享以下语义：七轴顺序 J1–J7、角度 deg、速度 deg/s、扭矩 Nm、单调时间戳、请求号、命令终态和反馈有效性。

## 2. Profile 与物理会话

产品 Profile 和物理连接不是同一个概念：

- 产品 Profile `aethor-robo-dual-7dof` 描述最终 Aethor_robo 双 7-DOF 的模型、关节组和显示信息。
- 物理会话由固件 `controller_id` 与 `arm_id` 标识。
- 首轮只有 `aethor-arm-controller-01 / arm-01`，只激活 7 个关节控件。
- 第二组完成后增加另一个控制器会话；Profile 仍可保持一个双臂产品。

在左右机械归属尚未确认前，UI 和协议使用 `Arm 01`，不要提前把首组写死为 Left 或 Right。机械装配锁定后，可在 Profile 中映射 `arm-01 → left-arm`，但固件稳定 ID 不应随显示名变化。

### 2.1 切换机制

控制台顶部的“当前机械臂”选择器切换活动会话：

```text
Aethor_robo
  ├─ Arm 01 · COMx · READY
  └─ Arm 02 · Offline / Pending
```

切换时：

- 停止向旧会话发送新的 UI 命令，但不自动停止旧机械臂。
- 保存每个会话各自的目标草稿、相机和图表选择。
- 实体模型切换到所选会话最新反馈。
- 幽灵模型先执行“目标对齐当前”，不能继承上一机械臂目标。
- 串口、使能、对齐、模式、活动命令和故障状态全部按会话隔离。
- 连接握手后调用 `GET_CONFIG`，比较固件 `map_hash` 与当前 Profile 的关节映射摘要；不一致时只开放诊断。

## 3. RobotGatewayV1 对齐

建议高层端口：

```ts
interface RobotGatewayV1 {
  listPorts(): Promise<SerialPortDescriptor[]>;
  connect(port: string, options: SerialOptions): Promise<RobotSessionSnapshot>;
  disconnect(sessionId: string): Promise<void>;
  getSnapshot(sessionId: string): Promise<RobotSessionSnapshot>;
  getConfiguration(sessionId: string): Promise<RobotConfigurationSnapshot>;
  subscribe(sessionId: string, onFrame: (frame: JointStateFrame) => void): Unsubscribe;
  alignReference(sessionId: string, qRefDeg: readonly number[]): Promise<CommandResult>;
  enable(sessionId: string): Promise<CommandResult>;
  stop(sessionId: string): Promise<CommandResult>;
  disable(sessionId: string): Promise<CommandResult>;
  clearFault(sessionId: string, joint?: number): Promise<CommandResult>;
  moveJoints(sessionId: string, command: JointGroupCommand): Promise<CommandHandle>;
}
```

`CommandHandle` 应分别暴露 `accepted` 和 `completion`，避免 UI 把 ACK 当完成：

```ts
interface CommandHandle {
  requestId: number;
  accepted: Promise<CommandAccepted>;
  completion: Promise<CommandResult>;
  subscribe(listener: (event: CommandProgress) => void): Unsubscribe;
}
```

`JointGroupCommand` 对七轴做严格校验：

```ts
type JointGroupCommand = {
  jointIds: [string, string, string, string, string, string, string]; // 当前会话绑定的 Profile 关节组稳定 ID
  targetDeg: [number, number, number, number, number, number, number];
  speedScale: number; // 0.01..1.00
  mode: 'POS_VEL' | 'MIT';
};
```

首组尚未确定装配到 Aethor_robo 左臂或右臂，因此不能把 wire contract 写死为通用 `joint_1..7`，也不能提前写死为 `left_arm_joint_1..7`。连接握手返回 `arm_id`，网关配置把它映射到 Profile 的 `left-arm` 或 `right-arm`，随后校验七个稳定关节 ID 和 `map_hash`。协议线上仍只传固定 J1–J7 顺序，不传 URDF 名称。

驱动控制模式由部署配置拥有。普通 `RobotGatewayV1` 只读当前模式，不提供运行时切换；若后续增加维护能力，应使用独立端口，并在驱动复位后销毁旧会话、清空 in-flight 和 alignment。

## 4. C# 网关实现要求

### 4.1 串口所有权

- 一个端口同时只能由一个 `SerialPortOwner` 打开。
- 所有读写在后台异步循环完成，UI 线程不直接访问 `SerialPort`。
- RX 按字节流分帧，不能假设一次 Read 就是一行。
- RX loop 持续运行并把完整帧交给 request ID 关联器；TX writer 只等待本次串口写入完成，不持锁等待 `ACK/RSP/DONE`。
- TX 使用有界优先级队列：P0 `STOP/DISABLE` 独立保留槽；P1 交互终端与结构化控制公平轮转；P2 HEARTBEAT/查询保留配额；P3 流配置与后台轮询。低优先级不得饿死心跳，高优先级也不得无限入队。
- 关闭会话时先取消读写循环，再关闭端口、释放 CTS/任务/事件订阅，最后发布离线快照。
- 错误 COM 口、打开失败或设备拔出后，必须允许显式断开和重新枚举。

### 4.2 请求关联和重试

- request ID 由网关会话单调分配，跳过 0。
- HELLO 返回的 `session` 保存到当前连接上下文，HEARTBEAT 必须回传该值。
- 每个 in-flight 请求用 `ConcurrentDictionary<uint, PendingRequest>` 管理。
- 查询只等待 `RSP/ERR`；命令先等待 `ACK/ERR`，再等待 `DONE`。
- pending request 只拥有结果关联和超时，不拥有串口写锁。等待某个设备响应期间，writer 仍可发送 STOP、交互查询、心跳或下一条被策略允许的帧。
- ACK 超时可用同一 request ID 有界重发一次，由固件幂等缓存防止重复动作；重试上限后不自动生成新 request ID。
- 最终结果超时先发送 `GET_STATE`，将 UI 状态显示为 `UNKNOWN`；不能自动重复 MOVE。
- 收到固件新的 `boot_id` 后，所有 in-flight 请求终止为 `CONTROLLER_RESTARTED`，清除 alignment 和本地命令门控，并要求重新握手。
- 网关每 250 ms 发送 `HEARTBEAT`；会话关闭时停止心跳。固件报告 `LINK_TIMEOUT` 后，网关重新查询真实状态，不沿用旧使能或活动命令。

### 4.3 遥测缓冲

- 网关保留每会话一份最新不可变快照。
- 对图表使用按信号有界时间环，默认 60 秒、最大 120 秒。
- 固件 50 Hz 数据可全部接收；前端渲染节流到 30–50 fps，避免每帧引发全页 React 重渲染。
- SignalR/IPC 背压时丢旧中间帧，始终保留最新帧和所有故障/命令事件。
- 记录固件帧序号间隙、网关丢帧和前端渲染丢帧，三者不能混为一个指标。

## 5. 数字孪生角度链路

唯一角度链路：

```text
DM3520 p_motor_rad
  → 固件 direction + zero_bias
  → TEL q_deg[7]
  → C# JointStateFrame.actualDeg[7]
  → 前端 degToRad
  → URDF joint_1..joint_7
```

下发链路：

```text
幽灵模型 targetDeg[7]
  → JointGroupCommand.targetDeg[7]
  → UART MOVE_JOINTS q_deg
  → 固件 soft limit + inverse alignment
  → DM3520 p_des rad
```

上位机不得再做 `direction`、零偏或减速比换算。否则会产生“双重反向”或“双重零偏”。Profile 中仍保留方向/限位是为了显示和前置校验，但连接时必须与固件 `GET_CONFIG.map_hash` 一致。

调试发现态允许每个 Arm 会话只出现任意电机子集。C# 将完整快照按 `motor_id 1…7` 映射到当前 Profile group 的第 1…7 个稳定关节，绝不按数组到达顺序映射。ID >7 进入 `unexpectedMotorIds`，重复/冲突进入 `duplicateMotorIds/conflictMask`，两者都不驱动模型关节。

### 5.1 实体与幽灵模型

- `actualDeg`：只由 `TEL JOINT_STATE` 更新实体模型。
- `targetDraftDeg`：滑条更新幽灵模型，不覆盖 `actualDeg`。
- “目标对齐当前”：复制一份同代、反馈有效的 `actualDeg` 到 `targetDraftDeg`。
- 下发后幽灵模型继续表示命令目标；实体模型持续跟随反馈。
- DONE 后不得直接把实体模型跳到目标，仍等待反馈帧。
- 反馈过期时冻结在最后值并显示 Stale，不伪造运动。
- 已收到完整发现快照后，缺失或冲突关节使用灰色材质；由于串联机构上游角度不可信会影响下游世界姿态，灰显从第一个不可信关节延伸到末端。下游已在线电机的自身角度仍可应用和查看，但整段姿态标为 `PARTIAL/UNCERTAIN`。

## 6. UI 状态与按钮门控

| 控件 | 启用条件 |
|---|---|
| 参考位对齐 | 已连接、七轴反馈有效、状态 `UNALIGNED/DISABLED`、无运动 |
| 当前模式 | 只读显示；模式维护不属于普通控制台 |
| 使能 | 已连接、已对齐、七轴反馈新鲜、无故障、模式已确认 |
| 下发整组关节角 | `READY`、已使能、目标 7 项合法、无活动 MOVE |
| STOP | 已连接且固件可接收命令；MOVING 时突出显示 |
| DISABLE | 已连接；允许重复执行 |
| 清错 | 去使能、无运动、存在可清故障 |

页面显示的命令状态：

| 状态 | 含义 |
|---|---|
| `Sending` | 网关正在写串口 |
| `Accepted` | 收到固件 ACK，机械动作尚未完成 |
| `Running` | 收到 RUNNING 事件或状态遥测 |
| `Settling` | 固件正在等待反馈稳定 |
| `Completed` | 收到 `DONE COMPLETED` |
| `Stopped` | 收到 `DONE STOPPED` |
| `Failed` | 收到 `DONE FAILED`，展示 reason |
| `Unknown` | 网关失去终态，先查询实际状态，由操作者决定下一步 |

收到 `DONE` 后立即释放当前命令门控，允许下一次操作。命令历史仍保留终态，但不能继续锁住发送按钮。

## 7. 参考位对齐 UI

建议流程：

1. 显示“本次上电尚未建立关节参考”。
2. 展示机械参考姿态示意、七个 `q_ref_deg` 和操作检查项。
3. 操作者确认机械臂已放到参考位后发送 `ALIGN_REFERENCE`。
4. 收到 `DONE COMPLETED` 后，实体模型立即按返回的 `q_deg` 更新。
5. 提供“逐轴方向验证”向导，每次只允许 ±小角度低速测试，并记录结果。

不能提供“一键保存驱动零点”替代本流程。驱动器零点、机械参考位和 URDF 零姿态的含义不同。

## 8. 动作编排

首版动作序列存于上位机：

```ts
type ActionStep = {
  id: string;
  name: string;
  targetDeg: SevenJointTuple;
  speedScale: number;
  mode: 'POS_VEL' | 'MIT';
  dwellMs: number;
};
```

执行器流程：

1. 检查所有步骤的 DOF、软限位、速度比例和模式一致性。
2. 发送当前步骤 `MOVE_JOINTS`。
3. 等待 `DONE COMPLETED`。
4. 可选等待 `dwellMs`，期间仍处理 STOP、故障和遥测。
5. 进入下一步。

STOP、DISABLE、断线、boot_id 变化或任一 FAILED 都终止本地序列并清空未执行步骤。重新开始必须由操作者显式确认。

## 9. 串口终端对齐

终端页面可以展示和导出原始 UART 帧，但结构化控制不应通过文本终端拼接完成。终端规则：

- 默认显示 `REQ/ACK/RSP/ERR/EVT/TEL/DONE`，提供隐藏周期 TEL 的开关。
- “隐藏 GET_JPOS”只影响显示，不停止底层协议和状态同步。
- Aethor Assisted 模式自动补 request ID 和 CRC；Raw 模式明确显示“只确认 transport write”，不把后续文本猜测为该次发送成功。
- 结构化控制和手工终端共用同一 `CommandDispatcher`，不能分别抢占串口。
- 交互终端使用 P1 队列，点击发送只等待有界入队与串口写入，不等待设备回复，因此一个未回复请求不会锁住下一次发送。回复由持续 RX loop 异步显示并按 request ID 关联。
- 固件仍只允许一个改变机械状态的活动命令；手工发送冲突 MOVE 时可以被固件返回 `BUSY`，但网关不得因等待上一条回复而阻止 STOP 或新的诊断查询写入。
- Dummy 与 Aethor 共用串口所有者、队列和协议帧视图，但分别使用 `dummy-ascii-v1` 与 `aethor-arm-ascii-v1` codec；不得让两个 adapter 同时解析或写同一 session。

## 10. 联调观测面板

为排查实时性与角度不一致，控制台或诊断页至少显示：

- 固件控制周期 Hz、最近/最大周期和 deadline miss。
- 固件 TEL Hz、网关接收 Hz、浏览器渲染 Hz。
- 每轴 `q_deg/target_deg/error_deg/qd_deg_s/age_ms/valid`。
- CAN RX/TX/错误/overflow/bus-off、七帧 TX 偏斜。
- 当前 `controller_id/arm_id/boot_id/protocol/fw/mode`。
- 活动 request ID、预计时长、已运行时间和命令阶段。
- 当前对齐状态和配置摘要是否匹配。

## 11. 前后端契约更新清单

固件协议实现开始时，上位机需要同步新增或调整：

- `RobotSessionSnapshot`：Aethor_robo v2 适配层增加 `controllerId`、`armId`、`bootId`、`aligned`、`controlMode`、`feedbackAgeMs[7]`；不能直接破坏当前 Dummy wire v1.3。
- `JointStateFrame`：固定七轴元组，增加 `frameSeq`、`deviceTimestampUs`、`velocityDegPerSec`、`torqueNm`、`validMask`。
- `AethorArmMotorSnapshot`：增加 `presentMask/conflictMask/unexpectedMotorIds` 和每槽 `motorId/availability/feedbackAgeMs`；完整帧允许任意子集，重复/越界 ID 不进入角度数组。
- `JointGroupCommand`：为七轴 adapter 增加固定 7 项目标、`speedScale` 和模式一致性字段；现有 Dummy `speedDegS` 兼容边界需要单独迁移决定。
- `CommandResult`：区分 `accepted` 与最终 `result`，包含 `requestId/reason/elapsedMs/maxErrorDeg`。
- `ProtocolFrame`：支持 `REQ/ACK/RSP/ERR/EVT/TEL/DONE` 和 CRC 状态。
- `SignalDescriptor`：来源分别为 `MEASURED/COMMANDED/COMPUTED`。

变更这些契约时必须同时更新 Schema、固件协议文档、C# codec 测试和前端模拟数据，不允许各层各自定义一套命名。

## 12. 联调完成条件

- 连接后可明确识别控制器和协议版本。
- 七轴反馈 50 Hz 连续进入 C# 与前端，运动期间不暂停。
- `GET_JPOS` 与周期 TEL 的关节角语义一致。
- 参考位对齐后，实机角、滑条角和 URDF 角统一。
- 幽灵目标发送后，实体模型按真实反馈逐帧到达目标。
- ACK、运行、稳定和最终结果在 UI 中清晰分开。
- 完成、停止或失败后可以立即开始下一条合法命令。
- 断线、固件重启和错误端口不会留下虚假的连接/使能/活动命令状态。
