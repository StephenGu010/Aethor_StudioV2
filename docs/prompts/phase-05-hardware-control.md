# 阶段 5 提示词：安全硬件控制

目标是在只读链路稳定后，加入最小结构化硬件控制：连接/断开、刷新、使能、停止并去使能、回零、复位、模式 1–3 和显式整组关节下发。

## 任务

1. 在 C# 应用层建立命令仲裁器：命令 ID、session ID、单在途策略、许可门、超时、取消、审计和幂等边界。
2. 下发前校验连接、反馈新鲜、已使能、模式能力、六轴数量、有限数值、关节限位、显式速度、完整四参数运动包络和无在途命令。UI 禁用只是辅助，后端必须重复校验。
3. 目标草稿必须显式提交整组六轴；3D 拖动、滑块、展示位预览和目标对齐均不自动发送。
4. 为使能、回零、复位、整组运动提供清晰确认。固件即时 ACK 只表示接收时，UI 不得显示物理完成。
5. 实现防御式停止链 `!STOP → $0,0,0,0,0,0 → !DISABLE → #GETENABLE`。只有读回 0 显示已去使能；失败或超时显示未确认和物理急停提示。
6. 先 fake serial、再状态控制门、再独立的低风险运动门。运动门必须有可追溯的速度上限、到位容差、连续稳定窗口和总超时；不要推断这些参数或安全回位姿态。

## 验收

- 非法状态和非法目标在后端被拒绝且未写串口；重复点击不会生成并发运动命令。
- 模式 1–3 语义与固件一致；模式 4/5 和排除命令无结构化入口。
- 断线、反馈陈旧、命令超时立即锁定下发。
- 监督实机逐项记录预期与实际；停止链必须证实 `#GETENABLE=0`。

完成后写 `docs/handoffs/phase-05.md`，列出实机动作、姿态、操作者、日志和任何未确认结果。
