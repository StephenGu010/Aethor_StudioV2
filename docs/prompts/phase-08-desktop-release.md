# 阶段 8 提示词：WebView2、发布与最终交接

目标是交付可安装的 Windows 桌面版，完成原生窗口能力、进程生命周期、DPI/字体、发布验收和最终交接。

## 任务

1. 在 `apps/studio-desktop` 实现 WebView2 自定义标题栏、最小化、最大化/还原、关闭、拖动区域和 `DesktopBridgeV1` 能力检测。浏览器模式继续显示不可用，绝不模拟成功。
2. 桌面壳生成短期会话令牌、启动 loopback C# 网关、传递端口/令牌并监督健康；退出、崩溃和升级时回收子进程、串口句柄和临时数据。
3. 定义日志、配置、robot package 和动作文件的 Windows 应用数据路径与版本迁移；安装/卸载不得删除用户动作，除非用户明确选择。
4. 完成签名占位、版本号、构建产物、安装/升级/卸载脚本和发布清单；敏感信息不进入包或日志。
5. 验证 Windows 100%/125%/150%/200% DPI，本地字体 fallback，以及 1366×768、1920×1080、2560×1440；修复标题栏命中区、模糊、裁切和多显示器恢复。
6. 执行完整自动化、安装后 smoke test、网关崩溃恢复、拔线、关闭清理和监督硬件回归。
7. 更新根 README、架构、协议、运行/诊断说明、CHANGELOG、验收矩阵；生成最终 handoff，并在本机打开最终页面供用户检查。

## 验收

- 干净 Windows 环境可安装、启动、升级和卸载；离线启动仍能进入明确的展示模式。
- 原生窗口按钮只在 bridge 声明能力后启用；关闭后无遗留网关进程或 COM4 句柄。
- 四个工作区和动作编排在三档分辨率、四档 DPI 下无关键裁切、重叠、字体回退错误或键盘焦点丢失。
- 发布包中的版本、许可证、模型来源和未验证限制准确；所有真实硬件结果有监督证据。
- 完成 `docs/handoffs/phase-08-final.md`，打开已打包应用的数字孪生首页，等待用户最终验收。
