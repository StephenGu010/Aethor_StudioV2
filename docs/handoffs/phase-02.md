## 本阶段目标

在不接入 C#、串口或实机动作的前提下，完成展示级工业控制台的字体、比例、响应式布局、交互状态和五工作区信息架构；不实现关节拾取/拖动，也不实现动作编排文档与执行器。

## 已完成

- 统一石墨深色视觉 token、Windows 本地字体栈、字号/间距层级、等宽数值和高可见焦点环。
- 重平衡标题栏、导航、状态带、3D 画布、六轴控制区与底部趋势/表格/事件区。
- 1366×768 使用紧凑密度和内部滚动，1920×1080 使用基准布局，2560×1440 扩展有效画布与数据密度。
- 禁用设备选择、桌面窗口、软件急停和硬件操作的原因可通过键盘聚焦发现。
- 新增 `/actions` 动作编排信息架构入口，所有创建、导入和运行入口保持禁用并明确归属阶段 6。
- 保存三档 Win32 数字孪生视觉基线，并将五工作区布局、安全状态和焦点行为纳入 E2E。
- 将 Canvas 阴影类型从 React Three Fiber 的弃用软阴影默认值改为 `PCFShadowMap` 映射。
- 将 `URDF READY` 收敛为真实资源状态：等待全部 visual/collision STL、再构建独立目标模型，并在两个渲染帧后上报；取消/失败时继续收束并释放迟到资源。

## 未完成与下一步

- Phase 3：实现六关节拾取、关节轴约束拖动、限位反馈和资源释放验收；拖动仍只能修改目标草稿与幽灵模型。
- Phase 4–5：实现 C# 只读网关和监督下的硬件控制安全门；本阶段没有串口能力。
- Phase 6：定义动作 JSON Schema、编辑器、导入导出、采集和逐点执行器；当前 `/actions` 不能保存或运行。

## 关键决策

| 决策 | 原因 | 影响 |
|---|---|---|
| 以 1920×1080 为基准，同时固化 1366×768 与 2560×1440 | 展示与现场设备分辨率差异较大 | 关键控制固定可达，紧凑视口仅在工作区内部滚动 |
| 禁用原因使用可聚焦说明容器 | 原生禁用控件不能获得键盘焦点 | 键盘用户能发现不可用原因，按钮本身仍不可触发 |
| Phase 2 增加动作编排路由但不增加动作能力 | 提前稳定产品信息架构，避免 Phase 6 再改主导航 | 当前没有 Schema、持久化或执行路径，不会伪造进度 |
| 视觉截图作为受版本控制的测试资产 | 布局比例回归难以仅靠 DOM 断言发现 | 视觉变化必须显式审阅并更新 Win32 基线 |
| READY 由资源完成与真实渲染帧共同驱动 | URDF 根回调早于异步 STL，旧状态会产生空模型截图和过早目标克隆 | 三档测试使用 15 秒有界状态等待；不以固定延迟冒充完成 |

## 已知风险与限制

- `THREE.Clock` 弃用警告来自 React Three Fiber 9.7 与 Three.js r185 的依赖组合，不影响当前渲染且没有被过滤；在 Phase 3 评估兼容升级并重新验证 3D 生命周期。
- 视觉基线当前固定为 Win32 Edge；Phase 8 仍需覆盖 WebView2、Windows DPI 和桌面标题栏能力。
- 1366×768 允许工作区内部滚动，但文档级页面不得产生横向滚动；E2E 已固定该边界。
- 本机 5173 被非权威服务占用，人工复核临时使用 5174；这不是仓库配置变更，标准开发端口仍为 5173。
